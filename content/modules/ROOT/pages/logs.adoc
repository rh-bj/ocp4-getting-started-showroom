= 로그

쿠버네티스/OpenShift 클러스터 전반에서 로그를 수집하고 확인하는 "프로덕션 준비" 방식은 다양합니다. 많은 사람들이 ELK(ElasticSearch, Logstash, Kibana)나 EFK(ElasticSearch, FluentD, Kibana) 계열을 선호합니다.

여기서는 개발자가 pod 안에서 실행 중인 애플리케이션의 동작을 이해하는 데 필요한 것들에 초점을 맞춥니다. 컨테이너 환경에서는 애플리케이션에 직접 접속해 로그 파일을 열어 볼 수 없기 때문에, ``kubectl logs``로 컨테이너의 표준 출력(stdout)을 조회하는 것이 애플리케이션 동작을 확인하는 기본적인 방법입니다.

실습에 사용할 Deployment를 하나 배포합니다:

[#create-deployment]
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
cat <<EOF | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
        env: dev
    spec:
      containers:
      - name: myapp
        image: quay.io/rhdevelopers/myboot:v1
        imagePullPolicy: Always
        ports:
        - containerPort: 8080
EOF
----

복제본이 3개(애플리케이션의 pod/인스턴스 3개) 실행 중인지 확인합니다:

[#logs-get-replicas]
[.console-input]
[source, bash]
----
kubectl get deployment my-deployment -o jsonpath='{.status.replicas}{"\n"}'
----

그렇지 않다면 3개로 스케일업합니다:

[#logs-scale-replicas]
[.console-input]
[source, bash]
----
kubectl scale --replicas=3 deployment/my-deployment
----

[.console-output]
[source,bash]
----

----

[.console-input]

`-f` 파라미터로 로그를 실시간으로 따라갈 수 있습니다:

[#logs-log-deployment-follow]
[.console-input]
[source, bash]
----
kubectl logs my-deployment-5dc67997c7-m7z9f -f
----

방금 실행한 ``logs -f``는 아직 아무것도 출력하지 않고 있을 것입니다 — 애플리케이션이 아직 요청을 받은 적이 없기 때문입니다. 다른 터미널을 열어 해당 Pod에 직접 요청을 보내서, 그 로그 창에 새 줄이 나타나는지 확인해 봅시다:

[.console-input]
[source,bash]
----
kubectl exec -it my-deployment-5dc67997c7-m7z9f -- /bin/bash
curl localhost:8080
----

[.console-output]
[source,bash]
----
Aloha from my-deployment-5dc67997c7-m7z9f
----

지금까지는 Pod 이름을 정확히 지정해서 로그를 확인했습니다. 하지만 복제본이 3개나 있는데 매번 어떤 Pod가 요청을 처리할지 어떻게 알 수 있을까요? 이를 확인하기 위해 먼저 ``my-deployment``를 위한 Service를 배포합니다:

[#create-service]
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Service
metadata:
  name: the-service
spec:
  selector:
    app: myapp
  ports:
    - protocol: TCP
      port: 80
      targetPort: 8080
  type: LoadBalancer
EOF
----

다른 터미널에서 해당 service에 반복해서 curl 요청을 보냅니다:

:section-k8s: logs
:service-exposed: the-service
include::partial$env-curl.adoc[]

요청을 반복해서 보내기 시작합니다:

include::partial$loop.adoc[]

이제 요청이 3개의 Pod에 나뉘어 도착하고 있으므로, 특정 Pod 하나만 지켜봐서는 전체 그림을 볼 수 없습니다. Deployment를 대상으로 `--all-pods` 옵션을 추가하면, 그 Deployment에 속한 모든 Pod의 로그를 한 화면에 모아 볼 수 있습니다. 각 줄 맨 앞에 표시되는 Pod 이름으로 어떤 Pod가 요청을 처리했는지 구분할 수 있습니다:

[#all-pods]
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
kubectl logs -f deployments/my-deployment --all-pods
----

[.console-output]
[source,bash]
----
my-deployment-5dc67997c7-5bq4n myapp Aloha from my-deployment-5dc67997c7-5bq4n
my-deployment-5dc67997c7-m7z9f myapp Aloha from my-deployment-5dc67997c7-m7z9f
my-deployment-5dc67997c7-s4jc6 myapp Aloha from my-deployment-5dc67997c7-s4jc6
my-deployment-5dc67997c7-s4jc6 myapp Aloha from my-deployment-5dc67997c7-s4jc6
----

----
