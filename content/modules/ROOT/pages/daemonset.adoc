= DaemonSet
include::vars.adoc[]
include::_attributes.adoc[]

지금까지 배운 Deployment는 "이 Pod를 N개 실행하라"고 지시할 뿐, __어느 노드__에서 실행할지는 스케줄러가 알아서 정합니다. 그런데 로그 수집기나 모니터링 에이전트처럼 __모든 노드마다 정확히 하나씩__ 떠 있어야 하는 종류의 워크로드도 있습니다. 이런 용도로 쓰이는 것이 DaemonSet입니다.

DaemonSet은 모든 노드가 Pod의 복사본을 하나씩 실행하도록 보장합니다.
클러스터에 노드가 추가되면 그 노드에도 Pod가 자동으로 추가됩니다.
노드가 삭제되면 Pod는 다시 스케줄되지 않고 함께 삭제됩니다.

== 준비

DaemonSet의 효과는 노드가 여러 개일 때 가장 잘 보입니다. 우리가 사용하는 OpenShift 클러스터에는 이미 여러 개의 워커 노드가 있으므로, 별도의 준비 없이 바로 노드 수를 확인해 봅시다:

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc get nodes
----

== DaemonSet

DaemonSet은 쿠버네티스의 `DaemonSet` 리소스를 사용해서 생성합니다. Deployment와 달리 `replicas` 필드가 없다는 점에 주목하세요 — 몇 개를 띄울지는 우리가 정하는 것이 아니라, 노드의 개수가 그대로 결정합니다:

[source, yaml]
----
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: quarkus-daemonset
  labels:
    app: quarkus-daemonset
spec:
  selector:
    matchLabels:
      app: quarkus-daemonset
  template:
    metadata:
      labels:
        app: quarkus-daemonset
    spec:
      containers:
      - name: quarkus-daemonset
        image: quay.io/rhdevelopers/quarkus-demo:v1
----

DaemonSet을 배포하고, ``-o wide``로 각 Pod가 어느 노드(`NODE` 열)에 떠 있는지 확인합니다:

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc apply -f apps/kubefiles/quarkus-daemonset.yaml

oc get pods -o wide
----

[.console-output]
[source,bash]
----
NAME                      READY   STATUS    RESTARTS   AGE   IP           NODE            NOMINATED NODE   READINESS GATES
quarkus-daemonset-jl2t5   1/1     Running   0          23s   10.244.0.2   multinode       <none>           <none>
quarkus-daemonset-r64ql   1/1     Running   0          23s   10.244.1.2   multinode-m02   <none>           <none>
----

모든 노드에 Quarkus Pod 인스턴스가 하나씩 배포된 것을 확인할 수 있습니다.

=== 정리

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc delete -f apps/kubefiles/quarkus-daemonset.yaml
----
