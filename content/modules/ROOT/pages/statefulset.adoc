= StatefulSet
include::vars.adoc[]
include::_attributes.adoc[]
:watch-terminal: 터미널 2

``StatefulSet``은 **각 Pod에 고유하고 안정적인 식별자를 부여하면서 여러 Pod를 관리하는 컨트롤러**입니다.

앞에서 살펴본 ``Deployment``가 일반적으로 서로 구분할 필요가 없는 동일한 Pod들을 관리한다면, StatefulSet이 생성하는 Pod에는 각각 고유한 이름과 순서가 부여됩니다.

예를 들어 replicas를 3개로 설정하면 다음과 같은 이름의 Pod가 생성됩니다.

[source,text]
-------
myapp-0
myapp-1
myapp-2
-------

이 이름은 단순히 우연히 생성된 이름이 아니라 각 Pod의 **고유한 식별자(ordinal)** 입니다. Pod가 장애로 인해 다시 생성되더라도 동일한 식별자를 유지합니다.

[source,text]
-------------------------------
myapp-0  → 삭제 → 다시 생성 → myapp-0
myapp-1  → 삭제 → 다시 생성 → myapp-1
myapp-2  → 삭제 → 다시 생성 → myapp-2
-------------------------------

StatefulSet은 다음과 같이 각 Pod의 상태와 식별성이 중요한 애플리케이션에 유용합니다.

* 각 Pod가 **고유하고 안정적인 네트워크 이름**을 가져야 하는 경우
* Pod가 다시 생성되더라도 **자신만의 영구 스토리지**를 계속 사용해야 하는 경우
* Pod를 생성하거나 삭제할 때 **일정한 순서**가 필요한 경우

대표적인 예가 데이터베이스나 분산 시스템입니다.

예를 들어 애플리케이션이 첫 번째 Pod와 두 번째 Pod를 서로 구분해야 한다면 다음처럼 안정적인 이름을 활용할 수 있습니다.

[source,text]
------
mydb-0
mydb-1
mydb-2
------

이러한 이름을 기반으로 애플리케이션이 ``mydb-0``을 초기화 인스턴스로 사용하거나, 각 Pod마다 서로 다른 역할을 부여하도록 구성할 수 있습니다.

=== StatefulSet과 Headless Service

StatefulSet에서는 각 Pod가 안정적인 네트워크 이름을 가질 수 있도록 일반적으로 **Headless Service**를 함께 사용합니다.

일반 Service는 여러 Pod를 하나의 주소 뒤에 묶어 사용하기 때문에 클라이언트 입장에서는 어떤 Pod에 연결되는지 알 필요가 없습니다.

[source,text]
----------
                 ┌─ myapp-0
Client → Service ─ myapp-1
                 └─ myapp-2
----------

반면 StatefulSet에서는 특정 Pod를 직접 식별해야 하는 경우가 있습니다.

Headless Service를 사용하면 각각의 StatefulSet Pod에 대해 안정적인 DNS 이름을 사용할 수 있습니다.

[source,text]
----------------------
myapp-0.<service-name>
myapp-1.<service-name>
myapp-2.<service-name>
----------------------

즉, Headless Service의 목적은 여러 Pod를 하나의 주소로 감추는 것이 아니라 **각 Pod를 개별적으로 찾을 수 있도록 네트워크 식별자를 제공하는 것**입니다.

이제 StatefulSet을 직접 생성하면서 이러한 동작을 확인해 보겠습니다.

== StatefulSet

StatefulSet은 쿠버네티스의 `StatefulSet` 리소스를 사용해서 생성합니다:

[source, yaml]
----
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: quarkus-statefulset
  labels:
    app: quarkus-statefulset
spec:
  selector:
    matchLabels:
      app: quarkus-statefulset
  serviceName: "quarkus" # <.>
  replicas: 1
  template:
    metadata:
      labels:
        app: quarkus-statefulset
    spec:
      containers:
      - name: quarkus-statefulset
        image: quay.io/rhdevelopers/quarkus-demo:v1
        ports:
        - containerPort: 8080
          name: web    
----
<.> ``serviceName``은 이 ``StatefulSet``을 관장하는 (headless) service의 이름입니다. 이 service는 StatefulSet보다 먼저 존재해야 하며, 세트의 네트워크 식별성을 책임집니다.

[#hostname-formula]
다음 "공식"을 사용하면 ``StatefulSet``에 속한 어떤 pod의 호스트 이름이든 예측할 수 있습니다:

****
`StatefulSet.name` + `-` + "ordinal index" 
****

"서수 인덱스"는 ``StatefulSet``이 생성한 첫 번째 pod에서 ``0``으로 시작하는 숫자이며, 추가되는 복제본 pod마다 1씩 증가합니다. 따라서 이번 경우, 위 ``StatefulSet``의 첫 번째 pod는 다음과 같은 호스트 이름을 가질 것으로 예상할 수 있습니다:

****
`quarkus-statefulset-0`
****

마지막으로, 앞서 언급했듯이 StatefulSet의 pod로 트래픽을 라우팅하려면 **headless service**도 만들어야 합니다:

[source, yaml,subs="+quotes"]
----
apiVersion: v1
kind: Service
metadata:
  name: #quarkus# #<.>
  labels:
    app: quarkus-statefulset
spec:
  ports:
  - port: 8080
    name: web
  clusterIP: None #<.>
  selector:
    app: quarkus-statefulset
----
<.> 이 값이 ``StatefulSet``의 `serviceName` 필드와 일치한다는 점에 주목하세요. dns 항목을 생성하려면 반드시 일치해야 합니다.
<.> ``clusterIP``를 ``None``으로 설정하는 것이 service를 "headless"로 만드는 부분입니다.

앞서 살펴본 ``StatefulSet``과 그에 대응하는 headless service를 생성하기 위해 다음 ``.yaml``을 클러스터에 적용합니다:

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
cat <<EOF | oc apply -f -
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: quarkus-statefulset
  labels:
    app: quarkus-statefulset
spec:
  selector:
    matchLabels:
      app: quarkus-statefulset
  serviceName: "quarkus"
  replicas: 1
  template:
    metadata:
      labels:
        app: quarkus-statefulset
    spec:
      containers:
      - name: quarkus-statefulset
        image: quay.io/rhdevelopers/quarkus-demo:v1
        ports:
        - containerPort: 8080
          name: web
---
apiVersion: v1
kind: Service
metadata:
  name: quarkus
  labels:
    app: quarkus-statefulset
spec:
  ports:
  - port: 8080
    name: web
  clusterIP: None
  selector:
    app: quarkus-statefulset
---
EOF
----

=== 안정적인 네트워크 식별성

앞서 **headless service**를 만든 이유는 stateful set의 pod들을 클러스터 __내부에서__ 찾을 수 있도록 하기 위해서였습니다(클러스터 외부에서 service에 접근하는 방법은 <<Exposing StatefulSets,Exposing StatefulSets>>를 참고하세요).

각 Pod가 생성될 때마다 `$(podname).$(governing service domain)` 형태의 DNS 서브도메인이 함께 부여되는데, 여기서 governing service는 StatefulSet의 `serviceName` 필드로 정의됩니다footnote:[쿠버네티스 공식 문서 link:https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/#stable-network-id[여기]도 참고하세요]

클러스터 내에 pod를 하나 만들고 클러스터 내부에서 ``nslookup``을 실행해 보면 이를 테스트할 수 있습니다. 다음 명령을 실행해서, 클러스터 로컬 `nslookup` 쿼리를 실행할 수 있는 pod를 네임스페이스에 생성하세요.

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc run -it --restart=Never --rm --image busybox:1.28 dns-test 
----

컨테이너 안에서 다음 명령을 실행해서 StatefulSet의 pod를 찾을 수 있는지 확인합니다.

[source,bash,subs="+macros,+attributes"]

----

== Exposing StatefulSets

앞에서 생성한 StatefulSet은 각 Pod에 **안정적인 네트워크 식별자**를 제공하기 위해 ``quarkus``라는 Headless Service를 사용합니다.
Headless Service는 `spec.clusterIP` 값이 ``None``으로 설정되어 있습니다.

먼저 우리가 생성한 Service를 확인해 보겠습니다.

[.console-input]
[source,bash,subs="+macros,+attributes"]
----------------------------------------
oc describe svc quarkus
----------------------------------------

출력에서 다음과 같이 ``IP``와 ``IPs`` 값이 ``None``으로 표시되는 것을 확인할 수 있습니다.

[.console-output]
[source,text,subs="+macros,+attributes,+quotes"]
------------------------------------------------
Name:                     quarkus
Namespace:                myspace
Labels:                   app=quarkus-statefulset
Annotations:              <none>
Selector:                 app=quarkus-statefulset
Type:                     ClusterIP
IP Family Policy:         SingleStack
IP Families:              IPv4
IP:                       None
IPs:                      None
Port:                     web  8080/TCP
TargetPort:               8080/TCP
Endpoints:                10.232.2.49:8080,10.233.4.26:8080,10.234.4.46:8080
Session Affinity:         None
Internal Traffic Policy:  Cluster
Events:                   <none>
------------------------------------------------

즉, 일반적인 ClusterIP Service와 달리 다음과 같은 하나의 Service IP가 만들어지지 않습니다.
Headless Service는 Service 자체의 가상 IP가 없고, 대신 DNS를 통해 backend Pod들의 endpoint 주소를 직접 알 수 있게 합니다.

그리고 statefulset을 만들면 이름으로 pod에 접근할 수 있도록, 쿠버네티스가 모든 `StatefulSet` pod에 레이블을 부여하게 되고, 이를 우리 service의 selector로 사용할 수도 있습니다.

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc describe pod quarkus-statefulset-2
----

축약된 출력에서 우리 레이블을 확인할 수 있습니다(강조 표시됨).

[.console-output]
[source,bash,subs="+macros,+attributes,+quotes"]
----
Name:         quarkus-statefulset-2
Namespace:    myspace
Priority:     0
Node:         devnation/192.168.49.2
Start Time:   Tue, 20 Jul 2021 04:45:04 +0000
Labels:       app=quarkus-statefulset
              controller-revision-hash=quarkus-statefulset-6bf5d59699
              #statefulset.kubernetes.io/pod-name=quarkus-statefulset-2#
Annotations:  <none>
----

이 레이블을 selector로 지정해서, 이 특정 pod를 대상으로 하는 service를 생성해보겠습니다. 

[.console-output]
[source,yaml,subs="+macros,+attributes"]
----
apiVersion: v1
kind: Service
metadata:
  name: quarkus-statefulset-2
  labels:
    app: quarkus-statefulset
spec:
  ports:
  - port: 8080
    name: web
  clusterIP: None
  selector:
    statefulset.kubernetes.io/pod-name: quarkus-statefulset-2 #<.>
----
<.> 쿠버네티스 StatefulSet 기능이 자동으로 제공하는 레이블을 활용하는 selector입니다.

service를 살펴봤으니 이제 생성해 봅시다:

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
cat <<EOF | oc create -f -
apiVersion: v1
kind: Service
metadata:
  name: quarkus-statefulset-2
  labels:
    app: quarkus-statefulset
spec:
  ports:
  - port: 8080
    name: web
  selector:
    statefulset.kubernetes.io/pod-name: quarkus-statefulset-2
EOF
----

그 사이에 터미널 1에서 요청을 보냅니다.

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
IP=$(oc get service quarkus-statefulset-2 -o jsonpath="{.spec.clusterIP}")
PORT=$(oc get service quarkus-statefulset-2 -o jsonpath="{.spec.ports[*].port}")
----

[#get-config-configmaps]
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
curl $IP:$PORT
----

다음과 같은 응답을 받게 됩니다.

[.console-output]
[source,bash,subs="+macros,+attributes,+quotes"]
----
Supersonic Subatomic Java with Quarkus quarkus-statefulset-2:1 #<.>
----
<.> 호스트 이름이 ``quarkus-statefulset-2``인 것에 주목하세요. 이것이 애초에 stateful set을 사용한 이유 중 하나로, pod가 예측 가능한 호스트 이름을 갖도록 하기 위해서입니다.



== 스케일 다운과 정리

=== 정리

이제 이 섹션의 끝에 도달했습니다. statefulset을 만든 yaml(그리고 external service)을 삭제하면 statefulset의 모든 요소를 정리할 수 있습니다.

[.console-input]
[source,bash,subs="+macros,+attributes"]
----
oc delete sts quarkus-statefulset
oc delete svc quarkus quarkus-statefulset-2
----
