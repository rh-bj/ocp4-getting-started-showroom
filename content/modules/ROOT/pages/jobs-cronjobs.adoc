== 배경지식: Job과 CronJob


지금까지 실습에서 주로 사용한 ``Deployment``는 웹 서버처럼 **계속 실행되면서 요청을 처리해야 하는 애플리케이션**에 적합합니다.

하지만 모든 애플리케이션이 계속 실행되어야 하는 것은 아닙니다.

예를 들어 다음과 같은 작업은 필요한 처리를 끝낸 뒤 종료되는 것이 정상입니다.

* 데이터베이스 데이터 정리
* 보고서 생성
* 대량 데이터 처리
* 백업
* 특정 파일 변환
* 일회성 관리 작업

Kubernetes에서는 이러한 **작업을 실행하고 완료 여부를 관리하기 위해 Job**을 사용할 수 있습니다.

=== Job

``Job``은 하나 이상의 Pod를 생성하여 **정해진 작업이 성공적으로 완료될 때까지 실행을 관리하는 Kubernetes 리소스**입니다.

가장 단순한 Job에서는 다음과 같은 흐름이 만들어집니다.

[source,text]
----
Job
 │
 │ Pod 생성
 ▼
Pod
 │
 │ 작업 실행
 ▼
프로세스 종료
 │
 ▼
Job Completed
----

일반적인 웹 애플리케이션에서는 프로세스가 종료되면 문제가 발생한 것으로 생각할 수 있지만, Job에서는 **작업을 성공적으로 끝내고 프로세스가 종료되는 것이 정상적인 동작**입니다.

예를 들어 다음과 같은 작업을 실행한다고 가정해 보겠습니다.

[source,bash]
----
echo "Hello from a Kubernetes Job"
----

명령이 정상적으로 실행되고 종료되면 Pod는 완료 상태가 되고 Job도 작업이 성공했다고 판단합니다.

Job은 Pod의 실행 결과를 추적하며, 작업이 실패한 경우 설정된 정책에 따라 다시 시도할 수도 있습니다.

=== CronJob

같은 작업을 정해진 시간마다 반복해서 실행해야 한다면 ``CronJob``을 사용할 수 있습니다.

CronJob은 Linux의 ``cron``과 비슷한 방식으로 **Cron 표현식에 따라 Job을 생성**합니다.

예를 들어 매일 새벽 2시에 데이터베이스 백업을 수행하거나, 매시간 보고서를 생성하는 작업을 CronJob으로 구성할 수 있습니다.

CronJob과 Job, Pod의 관계는 다음과 같습니다.

[source,text]
----
CronJob
   │
   │ 정해진 시간이 되면
   ▼
  Job
   │
   │ 작업 실행을 위해
   ▼
  Pod
   │
   ▼
작업 실행 후 종료
----

즉,

* **Job**: 작업을 한 번 실행하고 완료 상태를 관리
* **CronJob**: 정해진 일정에 따라 새로운 Job을 반복적으로 생성

한다고 이해하면 됩니다.

이번 실습에서는 먼저 Job을 직접 만들어 보고, 이어서 같은 작업을 CronJob으로 반복 실행하면서 ``CronJob → Job → Pod`` 관계를 확인합니다.

=== CronJob

:quick-open-file: whalesay-cronjob.yaml

CronJob은 쿠버네티스의 `CronJob` 리소스를 사용해서 정의합니다. ``cronjob``이라는 이름은 리눅스에서 유래한 것으로, 한 번 또는 반복적으로 실행되도록 예약된 일종의 배치 프로세스를 나타냅니다. 이 개념이 쿠버네티스에서는 `{quick-open-file}` 파일에서 볼 수 있듯이 다음과 같이 구현됩니다:

[source, yaml]
.{quick-open-file}
----
include::example$whalesay-cronjob.yaml[]
----
<.> 이 문자열은 job이 매분 실행됨을 나타냅니다.
<.> 여기서는 ``cronjob``이 생성하는 ``job``과 ``pod``에 적용하고 싶은 우리만의 추가 레이블을 지정합니다. `job-name` 레이블은 여전히 존재하지만, 매번 guid를 포함하게 되어 그 값을 미리 예측할 수는 없습니다.

[tabs]
====
터미널 1::
+
--
[.console-input]
[source,bash,subs="+macros,+attributes"]
----
cat <<EOF | oc apply -f -
apiVersion: batch/v1
kind: CronJob
metadata:
  name: whale-say-cronjob
spec:
  schedule: "* * * * *" 
  jobTemplate:                   
    spec:                        
      template:    
        metadata:
          labels:
            job-type: whale-say #<.>              
        spec:
          containers:
          - name: whale-say-container
            image: docker/whalesay
            command: ["cowsay","Hello DevNation"]
          restartPolicy: Never
EOF
----
--
====
